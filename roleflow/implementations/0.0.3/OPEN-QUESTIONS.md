## A. 打分与模型

### OQ-A1　第二级 deepRefine 用哪个模型？〔来源 R / 02〕
- 选项：`deepseek-reasoner`（强、贵、慢，JSON 模式待验证） vs `deepseek-chat`（够用、便宜）。
- **当前实现**：triage 与 deepRefine **都用 `deepseek-chat`**（`reasoner` 仅 digest/feedback-review 在用）。两级省钱靠 triage 提示词极小，不是靠换模型。
- 状态：已定。结论：两级均用 `deepseek-chat`（采用暂定默认）；如需更强判断，后续挑难例 A/B 再切 `reasoner`。

### OQ-A2　triage 升级阈值 `LLM_TRIAGE_MIN` 与每日预算上限？〔来源 R / 02〕
- 问题：粗评全量的 token 成本可接受范围？要不要 `LLM_DAILY_CALL_BUDGET` 硬上限？
- 状态：已定。结论：被 OQ-A5 取代——已无 triage 这一级，`LLM_TRIAGE_MIN` 移除；暂不设每日预算上限（成本由召回 + 短评压住），shadow 跑量后再看。

### OQ-A3　关键词层 threshold 调到多低？〔来源 01〕
- 问题：召回阈值降多少合适（召回率 vs 进 LLM 的量/成本）。
- **当前实现**：阈值**未下调**，保持原值（crypto 召回已 ~95%+）。
- 状态：已定。结论：阈值暂不下调；shadow 若发现漏召回再用 `analyze-passrate` 实测后降。

### OQ-A4　`events.score` 列存什么？〔来源 01〕
- 问题：继续存"召回分"还是存最终 `impact`。
- 状态：已定。结论：`score` 存召回分、`importance` 存最终冲击分；`triage_score` 列保留但不再使用（OQ-A5 取消了 triage 这一级）。

### OQ-A5　triage 与 deep 是否合并成一次调用？〔来源 02〕
- 倾向：先分开，简单可控。
- 状态：暂定（分开）。
- 决策：合成一次调用。甚至可以只做短评，不要全文评。
