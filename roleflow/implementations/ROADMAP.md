# 总体规划 · ROADMAP

> 这是**粗线条**的版本路线图，随时可能调整。
> 上半部分（北极星 / 演进主线 / 版本表）是稳定骨架；
> 下半部分「各版本细化」把每个版本按讨论展开，**多数是考虑与选项，不是已锁定的决策**。
> 真正可执行的细节看各版本目录（`0.0.x/`）里的 README 与 step 文档。

## 北极星

**事件驱动的自动交易**：抓尽可能多会影响交易的消息（主攻 crypto 与 A股），消息对交易影响越大、分越高；最终由系统自动判断方向、量级并执行交易。

核心认知——**分数 = 预期交易冲击，而不是关键词相关性**：

```
impact ≈ 意外度(actual vs 预期) × 量级 × 方向确定性
         × 受影响标的的流动性/弹性 × 信源可信度 × 延迟优势
```

已被市场 price-in 的事件（预告过的降准、排期内的解锁）关键词分很高但冲击≈0；未排期的突发（立案、被盗、闪崩）才是真 alpha。这条贯穿所有版本。

已锁定的大方向（讨论中拍板）：

- **crypto 先做深**（24/7、数据与执行 API 现成），A股 渐进跟上。
- **最终全自动下单**，但分阶段：先把"判断"做准 → 用真实行情校准 → 纸面验证 → 最后才碰真钱。
- **打分演进先搭"实际行情闭环"**：用实测涨跌反过来校准 LLM 的冲击判断。

## 演进主线

```
感知（看得准） → 校准（用真实行情验证判断） → 验证（纸面跑策略） → 执行（自动下单 + 风控）
```

## 各版本细化

> 下列细节按讨论展开，仅供后续规划参考；除"已锁定"标注外，均不构成决策。

### 0.0.1 ✅ MVP

- 主干：抓取（交易所 + PANews）→ 关键词加权过滤 → Telegram 推送。
- 价值：验证"抓取 → 过滤 → 推送"这条链路成立，作为后续一切的底座。

### 0.0.2 ✅ 稳定性 + 精筛基建

- 抓取层：每源独立 fetcher / UA 池 / Referer·Cookie·sec-fetch / 调度抖动，降低爬虫指纹。
- 能力基建：LLM 精筛层（`refine.service`）、跨源聚类、digest 简报、Telegram 👍/👎 反馈、推送后价格快照（effectiveness）。
- 注：LLM 精筛当时默认**关着**，只产 `importance/category`；收尾复盘修了 `AMA` 子串误杀、长正文低分词累加、并认清 **panews 主导是结构性的**（勿靠降阈值"平衡"）。这些是 0.0.3 打分重构的起点。

### 0.0.3 ◀ 当前 — 消息质量（详规见 `0.0.3/`）

- **打分内核**：关键词层降级为"召回初筛"（只决定值不值得过 LLM）；最终冲击分由**单次 LLM 调用**给（`deepseek-chat`，只喂标题 + 摘要做短评），产出 `方向 / 标的 / 意外度 / 视野 / 置信`。意外度=inline（已 price-in）要压低分。
- **信源**：crypto 做深（链上 / 衍生品 / 解锁日历 / 一手）；A股 最小可用（**只接 cninfo 巨潮**，财联社等反爬源推迟）。
- **双市场隔离**：crypto 与 A股 用不同规则集与 prompt，`market` 字段区分。
- **为终局预留**：`direction / tickers / surprise / horizon / detect_latency / market` 这版只抽取 + 存 + 展示，**不据此交易**。
- 进度：里程碑 A（打分内核 step 01+02）已落地并验证；crypto/A股 源扩展（03/04）待 API key 与采集调试。

### 0.0.4 规划 — 行情闭环（校准）

把 0.0.3 里"LLM 估的冲击分"用**真实行情**校准成"实测分"。crypto 先行。下列均为待实测定夺的选项：

- **视野网格**：事件交易的 alpha 在秒~分钟级，拟用 `+1m/5m/15m/1h/4h/24h`，替掉现有 `1h/24h/7d`（太粗，看不到窗口）。
- **测价范围**：对**所有打分候选**（含没推送的）测价，否则只看自己挑过的样本 → 选择偏差，学不到"漏掉的其实更会动"。
- **基线时点**：贴近**发布时刻**测基线；并单独记录 `detect_latency`（0.0.3 已落字段），因为全自动时这段延迟决定"还吃不吃得到"。
- **冲击指标**：用**超额收益**（扣 BTC/大盘 beta）+ **MFE/MAE**（窗口内最大有利/不利偏移），而非裸涨跌——MFE/MAE 还能直接告诉你"最多能赚多少、止损放多远"。
- **方向**：第一版可只做**无符号**"动没动 / 动多大"校准；signed P&L 需要方向（拽回 LLM 的 direction 字段）。
- **产出**：一张「event_type / 信源 / 当前冲击分桶 → 实测冲击分布」校准表，反过来改打分权重。
- 基建：现有 `effectiveness.service` + `price-snapshot.job` 是地基，扩成多视野 + 全候选 + 超额收益计算。

### 0.0.5 设想 — A股 做深

- 信源：接 **财联社电报**（7×24 快讯、强反爬，参考 panews 的 Cloudflare 经验）、交易所公告、互动易（投资者问答有时泄露信号）。
- 实体与传导：把 0.0.3 的"实体→代码 + 板块基础版"升级为较完整的**概念/板块传导图谱**（一条利好带动整条板块是 A股 重要 alpha）。
- 校准：A股 也接入 0.0.4 的行情闭环；注意 **涨跌停 / 交易时段**对"可成交性"的影响（封板了信号再准也吃不到）。

### 0.0.6 设想 — 策略与纸面交易

- 从"单条信号"升级为"策略"：进出场规则、持有期、止损（用 0.0.4 的 MFE/MAE 标定参数）。
- **paper trading**：系统"假装"下单、跟踪虚拟 P&L，在不动真钱的前提下验证策略是否真的赚钱；含手续费 / 滑点假设。

### 0.0.7+ 远期 — 自动执行 + 风控

- 接交易所 / 券商 API 真实下单；仓位管理、止损、单笔与总敞口限额、熔断。
- 用 0.0.4 积累的 `detect_latency` 数据决定**哪些事件类型值得自动打**（延迟敏感的让给机构，靠"解读"取胜的留给自己）。
- A股 自动交易的合规边界单独评估，必要时只在 crypto 上全自动。

## 贯穿各版本的设计思想

- **三级打分漏斗**：关键词召回（廉价、宁滥勿缺）→ LLM 结构化抽取（语义、方向、意外度）→ 量化叠加（结合行情上下文）。越往后量越小、成本越高。
- **意外度优先**：冲击 = 实际 − 预期。需要一本"预定事件日历"（财报、宏观数据、解锁、主网）来给"超预期的差值"打分，而不是给原始事件打分。（0.0.3 先靠 LLM 判断，系统化日历放后续。）
- **传导**：新闻 → 主标的 → 关联标的（A股 板块/概念、产业链；crypto 同类币联动）。
- **可信度与首发**：信源可信度加权；rumor → confirmed → 辟谣 的状态流转；同事件多源时推首发、记"谁更快"。

## 已知难点（贯穿、需持续应对）

- **A股 涨跌停**：封板则信号再准也成交不了，冲击分要把"可成交性"算进去。
- **回测前视偏差**：用 publish 时间而非 fetch 时间标注，别用未来信息。
- **反爬**：财联社/同花顺有 bot 检测；cninfo 相对友好，作 A股 第一落点。
- **合规**：A股 自动下单的边界；真钱最后碰。
- **延迟现实**：纯延迟拼不过机构，优势在"解读复杂事件"（政策、重组、复杂 M&A）。
- **24/7 vs 交易时段**：crypto 全天、A股 有盘前盘后与午休，"冲击何时兑现"不同。

## 贯穿原则

- **不重写，增量替换**：主干 `collect → normalize → filter → refine → cluster → notify` 一直保留，每版只在节点上加能力。
- **每步可灰度、可回滚、可观测**：改动带开关，"为什么推 / 不推 / 几分"全程可追。
- **为下一阶段预留接口**：当前版本不做的事，也把它需要的字段先记好（如 0.0.3 不交易，但先存 `tickers / direction / detect_latency`）。
- **真钱最后碰**：执行层放在信号质量与行情校验都过关之后。
